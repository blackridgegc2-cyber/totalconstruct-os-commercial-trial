# Live user/project access administration — 2026-10-15

Users / Access now loads actual company accounts rather than the legacy sample-user table. Click a name to edit its project assignments. The editor lists active company projects, supports selecting several projects, and allows a separate project role plus Role default / Allow / Deny for each module. Existing inactive project assignments remain visible for removal. Company admins/executives retain company-wide management rights and cannot be reduced through this project editor.

Changes are company-scoped, validated on the server, version-checked and audited. Complete assignment saves replace previous extra grants for the edited user's company. Project membership is changed through the audited RPC rather than direct browser writes. The current-session permission response now includes the project's complete effective set; stale or unavailable sets fail closed. Changes are detected by a 30-second permission refresh; server authorization takes effect immediately.

Restrictive table policies cover project RFIs, submittals, drawings, schedule, daily reports, meetings, tasks, safety, quality, pay applications, budgets, invoices and contracts where those tables carry project_id. Durable coordination and budget/import RPC checks use the same effective permissions. Explicit additions can enable module reads while existing base-role row restrictions remain intact. Company finance membership and other transaction-specific approval requirements remain separate; a project Allow does not grant company finance authority. This release does not certify every legacy privileged RPC or storage path as honoring every module deny; that broader review remains required before claiming full access isolation throughout all software modules.

Onboarding uses the same editor before sending an invitation. An administrator saves a validated access plan, and an auth-user creation trigger establishes the approved roles and project permissions transactionally before the auth service can deliver the invitation. The new flow does not accept arbitrary browser-supplied role grants. Existing accounts are directed to the access editor. Legacy owner/subcontractor invitation flows remain available outside this editor and are not certified by this release.

Validation: 48 Node tests; 22 new rolled-back database access checks, plus existing 19 import, 27 coordination and 23 CSI database checks; DOM emulation verifies live-name editing, active-project filtering, separate roles, denial retention and version submission. Invitation provisioning was tested with transient database identities and no email delivery. Full browser login/invitation acceptance remains outstanding.
